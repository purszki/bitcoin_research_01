21) Negative-query benchmark semantics corrected
- Updated:
  - `src/bench/research_bip158.cpp`
- Benchmark behavior now depends on scenario ground truth:
  - expected-positive queries still use first-match / early-exit timing
  - expected-negative queries now do a full scan over the relevant filter set instead of stopping at the first candidate match
- Applied symmetrically to:
  - Basic on-the-fly benchmark path
  - Hierarchical on-the-fly benchmark path
- Rationale:
  - early-exit timing is appropriate for positive existence queries because the client can stop once it has a candidate block
  - for expected-negative queries, early exit is not a reliable measurement because a probabilistic filter can produce an early false positive and make the run appear artificially fast
  - this effect became visible on the 50k scenario families, where one repeated absent-script query batch produced implausibly fast Basic timings due to early false-positive exit
  - full-scan negative timing is needed to measure the real filtering work for absence queries and to avoid overweighting accidental early false positives in aggregate comparisons

29) Fuse20 and Fuse32 filter implementations added
- Implemented `WideStorage<20>` template: uint32_t per slot in memory, bit-packed 20 bits/fingerprint serialization
- Added `Fuse20Filter` and `Fuse32Filter` classes following same pattern as Fuse16
- FPR: Fuse20 = 1/1,048,576, Fuse32 = 1/4,294,967,296
- Added prebuilt data structs and streaming builder support for both
- Ground truth validation passes for all filter types at 50k blocks

30) Fuse16+20 hierarchical filter with domain-separated keys
- Replaced old hierarchical GCS approach with a two-layer binary fuse filter design:
  - Outer layer: Fuse16 (1/65536 FPR) — scanned for all blocks
  - Inner layer: Fuse20 (1/1048576 FPR) — checked only on Fuse16 match
- Combined theoretical FPR: ~1/2^36
- Inner layer uses independent SipHash keys derived via domain separation:
  - Constants: INNER_DOMAIN_K0 = "Fuse20In", INNER_DOMAIN_K1 = "nerLayer" (as uint64_t)
  - Key derivation: CSipHasher(INNER_DOMAIN_K0, INNER_DOMAIN_K1).Write(k0).Write(k1).Finalize()
  - Swapped order for k1: CSipHasher(INNER_DOMAIN_K1, INNER_DOMAIN_K0).Write(k1).Write(k0).Finalize()
- Renamed from "Hier"/"Hierarchical" to "Fuse16+20" throughout benchmarks and scripts

31) Candidate-only optimization for Fuse16+20
- Previous approach: MatchAny(all_scripts) on both layers
- New approach: check Fuse16 per-script individually, collect candidates that pass
  - Only candidates (scripts that matched Fuse16) are verified against Fuse20
  - For a typical 180-script wallet, average ~1 candidate per FP block instead of 180
- Significant speedup for the inner layer check, especially for larger wallets
